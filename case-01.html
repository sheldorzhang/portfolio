从功能操作到目标驱动：AI-native 营销任务体验设计

产品

角色
参与 AI-native 营销任务体验重构，负责 Agent 基础配置与人机协作交互设计；主导 AI 体验设计体系建设，推动 AI Coding 与前端工程交付。
时间
2024 — 至今
关键词
AI-native / Agent UX / Multi-Agent / Human-in-the-loop / AI-ready Design System

01 产品与体验

MAGIC AI：让企业从营销目标出发，组织跨系统的增长任务

传统营销云已经具备人群圈选、活动编排、内容生产和效果分析等业务能力，但完成一场营销活动，运营人员仍需要在多个模块间组织数据、配置规则、协调策略与执行。

MAGIC AI 在既有 CDP（客户数据平台）、MA（营销自动化）等业务系统之上引入 Agent 能力，让用户直接表达营销目标，由 AI 协助拆解任务、调用业务能力，并在关键节点由用户确认，最终生成可核对、可应用的营销业务产物。

典型场景：沉默会员召回

MAGIC AI 基于企业营销数据与业务规则，由 Agent 组织任务，并调用营销云已有能力完成业务操作。

体验设计切入点：构建 AI-native 产品中的人机协作体验，支撑复杂营销任务

当 Agent 开始承担多步骤营销任务，体验设计需要重新组织用户与 AI 的协作方式：让用户在任务发起时明确目标与约束，在执行过程中理解状态并参与关键决策，在完成后核对产物、衔接后续业务操作。

我的设计围绕任务发起 → 理解与执行协作 → 结果验收与业务应用三个环节展开，让复杂营销任务变得可理解、可控制、可验收。

02 发现与定义

复杂营销任务，为什么需要新的协作方式？

一场营销活动往往涉及目标制定、人群圈选、策略匹配、活动配置和效果复盘。不同角色与业务系统分别承担其中的工作，运营人员需要持续协调目标、规则和执行结果。

跨角色协作：业务任务如何被接力完成？

以鞋服行业会员营销为例，通过业务流程梳理，呈现品牌运营、数据算法及代理团队在多个阶段中的协作关系，以及知识和业务规则对任务的支撑。

业务发现：营销任务的复杂度不仅来自功能数量，更来自跨角色、跨系统的依赖与信息交接。

用户体验地图：复杂业务如何影响运营体验？

从品牌运营人员的视角，进一步梳理完成营销活动所需的跨模块操作。

设计机会：从功能操作转向 AI-native 任务协作

传统 SaaS 通过 AI 功能提升单点效率，用户仍需自行组织任务；AI-native 产品则从业务目标出发，由 Agent 自主组织并完成任务，人在关键节点判断与确认。

业务观察与体验的核心变化

完整营销任务仍横跨多个业务模块，同一目标依赖运营人员持续协调。AI-native 的设计机会不在于替代现有业务系统，而在于重新组织任务、保持上下文，并改变人和 AI 的协作分工。

维度功能驱动目标驱动
产品体验AI 辅助局部操作，用户跨模块组织任务从目标发起，Agent 协助组织任务
AI 价值单点提效跨模块协作与业务产物交付
人的角色操作、配置与整合结果定义目标、判断、审核与验收

核心设计命题： 如何让营销目标、业务约束和任务成果在多步骤协作中保持关联，使用户能够理解 Agent 的行动、控制关键决策，并核对最终的业务结果？

03 体验策略

从用户痛点到产品目标，制定 AI-native 体验策略

MAGIC AI 从传统 SaaS 向 AI-native 升级，除了让 Agent 承接复杂营销任务，还需要解决任务发起门槛、业务交付可靠性和持续使用的问题。

结合业务场景与用户痛点，我们围绕任务激活（Activation）、交付质量（Task Quality）、持续活跃（Engagement）三个产品目标，探索不同的 AI 介入方式，并关联相应的使用与质量指标。

04 Agent 人机协作设计

从任务发起到成果应用，构建可理解、可控制的 Agent 体验

无论单 Agent 还是 Multi-Agent，用户都需要明确任务目标、理解执行进展，并参与关键决策。

围绕任务发起 → 理解与执行协作 → 结果验收与业务应用三个阶段，设计一致的人机协作体验。

01 任务发起｜降低目标表达与任务启动门槛

通过任务建议卡片、场景示例和输入引导，帮助用户理解 Agent 的能力范围，从营销目标发起任务，并按需补充人群、规则等业务约束。

02 理解与执行协作｜让关键决策清晰、执行过程可控

让用户在执行前确认 Agent 对目标的理解与计划，在执行过程中掌握关键进展，并在需要时参与判断。

澄清与计划确认

通过意图澄清（Clarify）补充缺失条件，通过计划确认（Plan Confirm）核对执行计划。任务相关的澄清与确认保留在对话上下文，系统级阻断提示则放在更容易及时处理的位置。

关键决策：Agent 执行过程如何展示？

从 Markdown 全量平铺转向按用户决策需求分层，优先呈现任务进度、关键状态与待确认事项，执行细节按需展开。

03 结果验收与业务应用｜让 Agent 产物进入真实营销流程

通过任务成果工作区（交付物侧边栏），关联执行记录与结构化业务产物，支持用户查看和核对策略、文案及 MA 活动配置，并衔接后续业务操作。

从具体交互到通用 AI 设计范式

将任务表达、协作确认与结构化产物中的共性交互，沉淀为 Compose、Collaborate、Artifact 三类组件及设计规则，支持不同 Agent 场景复用。

05 验证与总结

从真实业务反馈到持续优化的 AI 产品体验

MAGIC AI 的体验优化需要回到真实营销任务，通过客户交付反馈与数据验证识别问题，持续改进 Agent 的任务理解、执行协作和成果应用，并借助设计体系与工程化交付推动产品迭代。

02 AI 设计体系与工程化交付

围绕 Agent 的任务表达、协作确认和结构化成果，沉淀可复用的交互规则、组件与页面范式，并逐步整理为 AI 可理解、可使用的设计资产与工作流。

结合 AI Coding 与可运行原型验证设计方案，通过前端代码修改、设计走查与研发审核，推动体验问题修复和方案落地。

这些设计资产与协作方式为产品持续迭代提供了更稳定的交付基础，减少重复设计与实现偏差。

设计反思｜让 Agent 持续理解业务，创造真实价值

企业营销 Agent 的长期价值，取决于对业务场景、企业规则与用户决策的持续理解。

通过真实任务中的使用行为、结果质量与业务反馈，不断识别问题并优化产品，提升任务效率与业务成果质量。

让营销系统在持续使用与迭代中更懂业务，也更懂用户。
